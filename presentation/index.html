LabClear 4.0.0-rc3

Book a health check.
Understand your results.

A Thai-first chatbot for a simulated health-check clinic. It answers only from the clinic's own data, reads lab reports the customer confirms, and explains each value against the range printed on the same report, with sources.

Prices, centers, payments and lab reports are synthetic. No real patient data, no real money.

[0:10–0:25] Customers ask before the visit, while booking and after they get results. Staff answer the same questions every day, and only during opening hours. The owner set three rules: answer only from the clinic's data, be usable without help, and never be talked into discounts, other customers' data or invented policies.

From the report a customer has to the check-up they need

  1. Attach a photo or PDF of the reportRead in an isolated worker, then by Typhoon OCR, page by page
  2. The customer checks and confirms the valuesNothing is explained before confirmation
  3. Explanation with sourcesCompared only with the range printed on the same report; no diagnosis
  4. Ask about follow-up tests if wantedThe customer chooses; out-of-range values never trigger a sale
  5. Request a time; staff confirm; then payBookings and payments are previews until the customer confirms

Values read from a sample report, waiting for confirmation (offline test double)

[0:25–0:45] The core journey: attach a report, confirm what was read, get an explanation tied to the printed ranges, and book if you want. The model never decides a status; Python compares each value with the range on the report.

One FastAPI service on Render

  • Website and API togetherJinja pages and plain JavaScript, Thai first with an English switch
  • Chat pipelineguards, planner, roles, typed tools, runtime skills, writer, checks, reviewer
  • Provider gatenetwork switch, call cap, THB ledger and a free-only policy before every model call
  • Blueprintauto-deploys every commit on main; health check /ready
[0:45–1:00] Everything runs as one web service. Customers and staff reach the same FastAPI app. Data lives in PostgreSQL with encrypted rows. Every call to Typhoon or iApp passes the same gate that enforces a call cap and a 300-baht budget.

One message, step by step

  • The model proposes, Python decidesthe planner suggests a role and search terms; code checks permissions and calls the tools
  • Answers cite evidenceonly sources the tools returned; prices and report values checked in code; one rewrite, then withheld
  • Five model callsinput guard, planner, writer, reviewer, output guard
  • Every step is visiblestreamed live and kept under the answer as Process Explainability
[1:00–1:20] Thirteen steps, five of them model calls. If any check fails the answer is withheld and the customer sees which step stopped it. Nothing is invented to fill the gap.

[1:20–1:35] Each role can only call the tools its permissions allow. The Report Explainer has no sales tools. Skills are chosen per message and hash-checked, and the answer records which ones were used.

Managers tune the assistant without code, inside safety rails

  • Company Harnessturn unlocked skills on or off, add company wording, sources per search 1–8, answer length 500–4,000 tokens
  • Limits can only go downtool timeouts and item counts never exceed the code's ceiling
  • Lockedcore, evidence-citation and scope-uncertainty; safety checks; data permissions; customer confirmation
  • Knowledge library148 owner-approved records as A4 PDF pages; pause any record

Every save is a new revision that can be restored; its SHA-256 is recorded with each answer

[1:35–1:50] The owner asked for no-code control. Managers can shape the assistant, but cannot switch off the rules that keep it safe.
