# LabClear 3.0.2 — Guest ชั่วคราวและแก้ผลทดสอบรอบ 3

ฐาน: `f1d0e64876478017d8d829a6d7bf2ba4c04782b5` · สาขาส่งมอบ: `delivery/labclear-3.0.2`

## สิ่งที่เปลี่ยน

1. **Guest ตามตัวเลือก A**: คุยและอ่านภาพได้ภายในหน้าเดิม ข้อความ ภาพ แถวผลตรวจ session และ action อยู่ใน RAM ของเซิร์ฟเวอร์ ไม่เขียนลงฐานข้อมูลหรือ browser storage ไม่มี cookie สำหรับ Guest การรีเฟรช เปลี่ยนหน้าแบบเต็ม ปิดแท็บ หรือเข้าสู่ระบบจะทิ้งแชตชั่วคราว การสลับเมนูภายใน `/app` ยังใช้แชตเดิมได้ ปุ่ม New chat ล้างรายงานชั่วคราวด้วย
2. **ลดการบล็อกผิด**: คำตอบเรื่องบริการที่กล่าวถึงเลือดหรือผลตรวจไม่ถูกจัดเป็นข้ออ้างทางการแพทย์เพียงเพราะมีคำนั้น คำถามที่ระบุชื่อแพ็กเกจและไม่มีรายงานจะใช้ role ที่อ่าน catalog ได้ คำตอบที่ผิดราคา อ้างอิง แถวผลตรวจ ขอบเขต role หรือไม่ผ่าน reviewer แก้ได้หนึ่งครั้งรวมกัน แล้วตรวจซ้ำทั้งหมด หากยังผิดจะไม่แสดงคำตอบ
3. **แก้เส้นทางใช้งาน**: การกดเมนูเร็วไม่ให้ผลจากหน้าเก่าทับหน้าล่าสุด ฟอร์มจองรักษาแพ็กเกจ สาขา วันและเวลาระหว่างเข้าสู่ระบบ notification เก็บ query parameters ของปลายทาง ลิงก์ Staff inbox ไป service desk และปุ่ม Read my lab report เปิดเมนูแนบภาพ
4. **แก้กรณีงานตอบกลับช้า**: การปิด Guest ไม่ให้ AI/OCR สร้างข้อมูลกลับมา Stop ระหว่างอ่านภาพไม่ให้รายงานถูกใส่ในแชตใหม่ คำแนะนำให้ติดต่อแพทย์โดยเร็วเมื่อยืนยันแถวที่มี critical flag แสดงอยู่ในการ์ดแม้คำอธิบาย LLM ถูกระงับ

การสมัคร/เข้าสู่ระบบไม่ย้ายข้อความหรือภาพ Guest เข้าบัญชี ประวัติของบัญชีที่เข้าสู่ระบบยังทำงานตามเดิม Guest ต้องเข้าสู่ระบบก่อนส่งเรื่องให้เจ้าหน้าที่ สร้าง project หรือเปิดเอกสารรายงานในหน้าใหม่ เพื่อไม่ให้เกิดประวัติถาวรจากข้อมูลชั่วคราว

## การลบและขอบเขตที่ต้องทราบ

- หน้าเว็บส่งคำขอล้าง RAM ตอน `pagehide` และไม่มี token ให้หน้าใหม่กู้แชตกลับมา หากเบราว์เซอร์ถูกปิดโดยไม่ส่งคำขอ RAM จะหมดอายุหลังไม่มี request 20 นาที โดยมีตัวกวาดทุก 30 วินาที
- จำกัดแถวชั่วคราวรวม 64 MiB และ 100 page sessions ต่อ process เมื่อเต็มแจ้งให้ลองใหม่ ไม่มีการเปลี่ยนไปเก็บบนดิสก์ Multipart upload ที่ API ยอมรับคงอยู่ใน RAM ด้วย
- ใช้ entrypoint แบบ process เดียวของโครงการ การเพิ่ม worker โดยไม่มี affinity อาจทำให้ Guest ได้ 401 จึงต้องทบทวนสถาปัตยกรรมก่อนขยายจำนวน worker
- transaction แรกของรุ่นนี้ลบ Guest เว็บไซต์แบบเก่าที่ไม่มีบัญชี พร้อมข้อมูลที่เป็นเจ้าของและ notification/audit ที่อ้างถึง ข้อมูลบัญชี password, Google และ LINE ที่ยืนยันตัวตนแล้วไม่ถูกลบ สำเนาสำรองเก่าของผู้ให้บริการยังขึ้นกับการเก็บรักษาของเจ้าของระบบ
- ผู้ให้บริการ AI/OCR ยังคงรับเนื้อหาที่จำเป็นสำหรับคำขอนั้น การไม่เก็บประวัติใน LabClear ไม่ใช่การเปลี่ยนนโยบาย retention ของผู้ให้บริการ
- โควตาการอ่านของ Guest นับภายในหน้าปัจจุบัน; rate limit, provider call cap และงบประมาณรวมยังทำงาน

## Guardrail ตาม Week 11

อ้างอิงเอกสาร `Week 11.pdf` ที่เจ้าของส่ง (18 หน้า): input/output guards, defense in depth, least privilege, fail closed และข้อจำกัดของ regex ที่บล็อกคำปกติได้

| ประเด็น | การบังคับใช้ในรุ่นนี้ |
|---|---|
| Input, document และ output guard | ยังเรียก guard ทุกจุดเดิม บริการล่มหรือผลอ่านไม่ได้ไม่ถือว่าปลอดภัย |
| การอ้างอิง/ข้อมูลผิด | ตรวจ citation IDs, source type, ราคาและแถวผลตรวจ ก่อน reviewer และ output guard |
| False positive | ปรับเฉพาะ heuristic ที่จับคำเรื่องบริการผิดและ routing ของ role ไม่ลดเกณฑ์อนุญาตคำสั่งอันตราย |
| Least privilege | role เห็นเฉพาะแหล่งข้อมูลที่อนุญาต และ backend ตรวจเจ้าของข้อมูลทุกครั้ง |
| การทำรายการ | LLM เสนอ preview เท่านั้น การจอง/จ่ายเงิน/ส่งต่อยังต้องยืนยันผ่าน backend |
| ค่าใช้จ่าย | แก้เนื้อหาได้หนึ่งครั้งต่อคำตอบ ไม่มี retry วนไม่สิ้นสุด; call cap และ ledger เดิมยังใช้ |
| ความลับ/การแสดงผล | token Guest ไม่อยู่ใน URL, cookie หรือ Web Storage; log การแก้คำตอบบันทึกเฉพาะ reason code; UI ใช้ตัวแสดงผลที่กรอง HTML เดิม |

## นำเข้า main และ push

bundle มี commit แล้ว ไม่ต้อง `git add` หรือสร้าง commit ซ้ำ คัดลอกไฟล์จาก ZIP ไป Downloads แล้วเรียก PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\LabClear-3.0.2\Import-LabClearBundle.ps1" -Push
```

สคริปต์ใช้ repo `C:\Users\User\Desktop\myProject\LabClear` ตรวจว่ามีไฟล์แก้ค้างหรือไม่ สลับ main, pull แบบ fast-forward, verify bundle, fetch, merge แบบ fast-forward แล้ว push `origin main` เมื่อระบุ `-Push` หากประวัติแยกกันหรือมีไฟล์ค้างจะหยุดโดยไม่ reset หรือทับไฟล์ สามารถระบุ `-Repo` และ `-Bundle` ได้

หลัง Render แสดง Deploy live ให้รันจาก repo:

```powershell
.\scripts\Run-LabClearEval.ps1 -Round 4
```

สคริปต์สร้าง `.venv` ด้วย Python 3.12 หากยังไม่มี ติดตั้ง requirements ตรวจ `/health` ให้ commit ตรงกับ main ในเครื่องก่อนเริ่ม แล้วเรียก `course_eval` ซึ่งใช้ผู้ให้บริการจริงและมีค่าใช้จ่าย ส่งไฟล์ `course_eval_round4.json` กลับมาเพื่อทบทวนความถูกต้องทุกกรณี หาก PowerShell บล็อกไฟล์ ใช้ `powershell -ExecutionPolicy Bypass -File .\scripts\Run-LabClearEval.ps1 -Round 4` เฉพาะคำสั่งนั้น

ทดสอบเองแบบไม่ใช้โมเดลจริงได้ด้วย `.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt` แล้ว `.\.venv\Scripts\python.exe -m pytest -q` ส่วน Playwright ใช้ `npm ci`, `npx playwright install chromium`, `npm run uat`
