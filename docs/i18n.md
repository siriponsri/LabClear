# Interface language

How the website, the customer workspace and the service desk switch between Thai and English. This page is for maintainers. The language of the assistant's answers is a separate rule; see [chatbot-spec.md](chatbot-spec.md#language-and-tone).

## Rules

- Thai is the default interface language. English is shown when the visitor chooses it with the TH/EN switch.
- Templates and scripts are written in English. Thai comes from a dictionary and is applied in the browser.
- Technical or formal terms may stay in English when a Thai translation would be harder to understand (owner's rule). Examples: Company Harness, Process Explainability, runtime skills, typed tools. Thai sentences keep them as written, for example "เลือก skills ที่ผ่านการตรวจทานและ typed tools ที่ผู้ช่วยใช้" (`i18n/th/rc3.overrides.json`). Package and plan names (Essential Check, LabClear Plus) also stay as named.
- Content is not interface text and keeps its own language: chat messages, model answers, values read from a report, source titles, hospital offer details and names people typed.

## How the language is chosen

| Side | Behaviour | File |
|---|---|---|
| Server | `ui_lang(request)` returns `en` only when the `labclear_language` cookie is `en`; otherwise `th`. Templates render `<html lang="{{ lang }}">` and preload the Thai fonts when the language is Thai | `routers/site.py`, `templates/site/base.html`, `templates/workspace.html` |
| Browser | The TH/EN buttons (`.language-switch button[data-lang]`, marked `translate="no"`) call `LC_I18N.set()`. It writes the cookie (one year, `Path=/`, `SameSite=Lax`, `Secure` on HTTPS), swaps the text in place without a reload and fires the `labclear:language` event. Drafts, scroll position, open chats and dialogs stay as they are | `static/js/i18n.js` |
| API | Error and status messages from the server are English; the browser translates them like any other interface text | `scripts/i18n_api_messages.py` |

## How the translator works

[`static/js/i18n.js`](../static/js/i18n.js) loads in `<head>` before the body is parsed.

- It translates text nodes and the `aria-label`, `placeholder`, `title` and `alt` attributes. Page titles are translated part by part ("Health checks | LabClear"), keeping the name LabClear.
- A `MutationObserver` on the document translates whatever the parser and page scripts add, before the browser paints it, so Thai pages do not flash English.
- Keys are the English strings with whitespace normalized. A key may be a template with `{placeholder}` values ("{n} tests"); the most specific matching template wins.
- A sentence that wraps inline elements (links, emphasis, numbers) is translated as one unit: its key replaces each element with `{0}`, `{1}` and so on, and the Thai template puts the same elements, with their event listeners, back in Thai word order. Without such an entry each text piece is translated on its own.
- The English source of every translated node is kept, so switching back is exact.
- It skips `script`, `style`, `noscript`, `template`, `textarea`, `code`, `pre`, `kbd`, editable regions, anything inside `[translate="no"]` or `[data-no-translate]`, and any element that declares its own `lang` (other than `<html>`).

Window API: `LC_I18N.lang`, `.locale()` (`th-TH` or `en-GB`), `.t(en)`, `.tf(en, values)`, `.set(lang)`, `.translate(node)`, `.source(el)`.

To keep content in its own language:

- In a template, add `translate="no"`, or set `lang` with the helper `text_lang(value)` (returns `th` when the text contains Thai letters, otherwise `en`), as on `/hospital-links`.
- In a script, call `node.setAttribute('translate', 'no')`, as `static/js/turns.js` does for messages and answers.

## Dictionary

| Item | Detail |
|---|---|
| Sources | [`i18n/th.json`](../i18n/th.json) (strings carried over from 3.x) and every feature file in [`i18n/th/`](../i18n/th), merged in alphabetical order (a later file wins), then the reviewed corrections in `*.overrides.json`, which always win. Keys are the English strings exactly as written in `templates/` and `static/js/`; values must be strings |
| Build | `node scripts/build_i18n.mjs` writes `static/i18n/th.js` (`window.LC_TH = {...}`) and a reproducible gzip copy `static/i18n/th.js.gz`. Both are generated; do not edit them. The current build has 3,147 entries |
| Serving | `main.py` serves `th.js.gz` to browsers that accept gzip. The `?v=` asset version is a hash of the dictionary, the translator, the main stylesheets and `turns.js` (`routers/site.py`), so browsers can cache them for a year |
| API messages | `python scripts/i18n_api_messages.py` lists the user-facing English messages in `main.py`, `routers/` and `services/` (f-strings become `{placeholder}` templates) and exits 1 when `i18n/api-messages.en.json` is stale; `--write` regenerates it. `node scripts/build_i18n.mjs --check` fails when one of them has no Thai entry, exact or by template. Thai API messages live in `i18n/th/api-messages.json` |

To add or change a string:

1. Write the English text in the template or script.
2. Add the exact English key and its Thai value to the matching file in `i18n/th/`. Use `{name}` for values and `{0}`, `{1}` for inline elements.
3. If you added or changed a server message, run `python scripts/i18n_api_messages.py --write`.
4. Run `node scripts/build_i18n.mjs --check` and commit the regenerated `static/i18n/th.js` and `th.js.gz`.
5. Check the page with the audit below.

## Thai line breaking

Browsers break Thai lines with the ICU word dictionary. Loanwords and medical terms that ICU does not know are cut mid-word ("แพ็ก|เกจ"), and the words after them can be mis-segmented too ("แชตนั้นพร้อม" becomes แช|ตนั้|นพ|ร้|อม). On a narrow screen a line can then break inside a syllable.

| Item | Detail |
|---|---|
| Word list | [`i18n/th-keep-together.json`](../i18n/th-keep-together.json): 38 reviewed words such as แพ็กเกจ, แชต, ครีเอตินิน, อัลบูมิน, พร้อมเพย์ |
| Protection | [`scripts/thai-keep.mjs`](../scripts/thai-keep.mjs), applied by the build: the letters of each listed word are joined with WORD JOINER (U+2060), so no line break can fall inside it; a ZERO WIDTH SPACE (U+200B) is placed at its edge when the neighbour is a Thai letter, so ICU starts the next word cleanly. It also keeps "ๆ" and the time suffix "น." from starting a line. Both characters are invisible, the step is idempotent, and the translator ignores them when matching |
| Candidates | [`scripts/thai_keep_words.py`](../scripts/thai_keep_words.py) tokenizes every Thai string with the PyThaiNLP dictionary, asks ICU (Node's `Intl.Segmenter`, through `thai-keep.mjs --segment`) how each string segments, and proposes the words ICU splits. `--write` updates the list; `--fresh` starts again from the built-in extra words. Review the list by hand: common words and PyThaiNLP mis-splits are left out |
| Judge | [`scripts/thai_break_check.py`](../scripts/thai_break_check.py) answers the i18n audit: a wrap is wrong when a Thai segment at the break is neither a dictionary word nor made only of dictionary words |
| Styles | [`static/css/i18n.css`](../static/css/i18n.css) sets taller Thai line heights, `overflow-wrap: break-word` with `word-break: normal`, balanced headings and no letter spacing or upper case on Thai labels. Manual line breaks are never inserted |

PyThaiNLP is a developer and test tool, not a runtime dependency: `pip install pythainlp`. The `_about` note in `th-keep-together.json` and the docstring of `thai_keep_words.py` still name an older merge script; the build script is `scripts/build_i18n.mjs`.

## Fonts

| Use | Font | Files in [`static/fonts/`](../static/fonts) |
|---|---|---|
| Thai text | IBM Plex Sans Thai (CSS family `PlexThai`) | `ibm-plex-sans-thai-thai-{400,500,600}-normal.woff2` |
| Thai headings (`h1`, `h2`, display text) | Trirong (CSS family `RSDisplayThai`) | `trirong-thai-{500,600}-normal.woff2` |
| Latin text and headings | Geist; Source Serif 4 | `geist-variable.woff2`; `source-serif-4-opsz.woff2` |

- The Thai files are self-hosted subsets. Their `unicode-range` (U+0E01–0E5B, U+200C–200D, U+25CC) sends only Thai characters to them, so Latin text stays in Geist and Source Serif 4 (`static/css/base.css`).
- All use `font-display: swap`. For a Thai page the website preloads the 400 text weight and the 600 heading weight; the workspace preloads the 400 text weight.
- All fonts are under the SIL Open Font License 1.1; the license files sit next to the fonts. See [NOTICE.md](../NOTICE.md).
- `IBMPlexSansThai-Regular.ttf` is used for Thai text in server-generated knowledge PDFs (`services/knowledge_admin.py`). The Noto Sans Thai and Noto Serif Thai files are for document and diagram builds, not the website.

## Audit

[`tests/browser/i18n_audit.mjs`](../tests/browser/i18n_audit.mjs) checks every website page, workspace view (`/app`), the printable Lab Report and every service-desk view (`/staff`), in Thai and in English, at 390, 768 and 1440 px wide:

- `<html lang>` and the TH/EN switch (visible, correct pressed state);
- interface text in the wrong language (`tests/i18n/audit-lib.mjs`), with the owner's English terms and package names allowed;
- Thai words split mid-word (PyThaiNLP judge; `NOT_RUN` without PyThaiNLP);
- clipped text, horizontal overflow, console and page errors;
- switching language on the page without a reload: the text changes and a chat draft survives;
- interaction states in both languages: sign-in error, chat send failure, slow loading, empty catalog search, 404.

It needs a running app with the offline AI stand-in:

```bash
PORT=8010 python scripts/dev_mock_api.py &
BASE=http://127.0.0.1:8010 I18N_OUT=test-results/i18n node tests/browser/i18n_audit.mjs
```

```powershell
# first window
$env:PORT = "8010"; python scripts/dev_mock_api.py
# second window
$env:BASE = "http://127.0.0.1:8010"; $env:I18N_OUT = "test-results/i18n"; node tests/browser/i18n_audit.mjs
```

`dev_mock_api.py` listens on port 8000 unless `PORT` is set, and the audit targets `http://127.0.0.1:8000` unless `BASE` is set. `I18N_ONLY=prefix,prefix` runs a subset and `I18N_WIDTHS=390,1440` limits the widths. Results go to `docs/evidence/current/i18n-audit.json` unless `I18N_OUT` is set; screenshots go to `eval_runs/i18n-shots/` (`I18N_SHOTS`). The script exits 1 on failure.
